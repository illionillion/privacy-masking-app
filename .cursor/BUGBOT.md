# Bugbot レビュールール

コメント・指摘は**日本語**で書くこと。

## レビュー優先順位

1. **高**: プライバシー破壊、実バグ、回帰、メモリリーク、アクセシビリティの破壊、重い処理のメインスレッド占有
2. **中**: このリポジトリ固有の契約違反（クライアント完結、Canvas/Worker の扱い、エディタ操作の抜け）
3. **低 / 原則無視**: 文言の好み、スタイルの好み、リファクタ提案のみ、Agent/IDE 作業手順への未準拠

## 必ずフラグすること

### プライバシー（最優先）

- 画像・`Blob`・`ImageData`・`canvas.toDataURL` / `toBlob` の結果を `fetch` / `XMLHttpRequest` / 外部 API へ送るコード
- アップロード画像の内容をサーバーや解析サービスに渡す実装

このアプリは**ブラウザ完結**が前提。画像データのサーバー送信はバグとして扱う。

### メモリ

- `URL.createObjectURL` の解放漏れ（`URL.revokeObjectURL` なし）
- Canvas / `ImageData` / 大きな一時バッファの破棄漏れ
- イベントリスナーや Worker の解放漏れによるリーク

### アクセシビリティ

- 操作可能な UI から `aria-*` / `role` / キーボード操作（Enter / Space / Escape）を落とす変更
- フォーカス管理の破壊（モーダル開閉、ダイアログ）
- 代替テキストやキャプション要件の欠落

### 処理の効率化

- 顔検出・OCR・モザイク等の重い処理を、既存が Worker 化しているのにメインスレッドへ戻す変更
- 大きな画像に対する不要な同期ループや、毎回フル再計算する明らかな回帰
- `toBlob` / `toDataURL` をメインスレッドで過剰に繰り返す実装

### Canvas / 座標・書き出し（該当差分があるとき）

- スタンプ・ペイント・crop などの論理座標は**元画像ピクセル空間**。Stage 座標・`viewZoom`・`scaleX/Y` との混同による位置ズレ・書き出しズレ
- `canvas.getContext("2d")` の null 未チェック
- `MAX_CANVAS_DIMENSION`（4096）の適用タイミング誤り（例: crop 前にフル画像を縮小してから切る、意図と違う解像度になる）
- 編集表示と `exportEditorCanvas` 等の書き出しで、クリップ・座標オフセット・効果適用の片方だけ直してプレビューと DL が食い違う
- Konva Transformer 後に `scaleX/Y` を 1 に戻さない、負スケール（反転）で幅・高さが壊れる、回転の有無の前提ミス
- エディタ上のプレビュー効果と書き出し経路で、モザイク等の実装が分岐したまま片方だけ更新される

### エディタ操作（該当差分があるとき）

- 新モード追加時に `touch-action` / ジェスチャ / Transformer 表示分岐の抜け（モバイルでスクロールと操作が競合する等）

## 無視してよいこと

- Prettier / インデント等のフォーマットのみの指摘
- 既存パターンを踏襲しているだけのスタイル差
- Issue・ブランチ命名などの開発フロー手順
- ドキュメントや更新記事の文体の好み
